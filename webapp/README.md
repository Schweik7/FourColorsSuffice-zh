# 《四色足矣》插图工作台

Vite + React + TypeScript。三个标签页：

- **地图绘制台** —— 在六边形网格上直接涂出区域，邻接关系从涂色里量出来。主力工具
- **SVG 生成器** —— 给一张邻接图，程序化生成对应的四色地图。作为绘制台的草稿来源
- **插图校对台** —— 原书扫描件与重绘 SVG 并排对照审阅（原来的 `review.html`）

```bash
pnpm install
pnpm dev        # http://localhost:5173
pnpm build      # 产物在 dist/
pnpm test       # 输入解析 + 校对进度导入 + 生成算法 + 涂色链路，四套
```

`pnpm smoke --write` 与 `pnpm paint-test --write` 会把各用例生成的 SVG 落到 `scripts/out/`，方便肉眼检查。

插图不在本目录里——`plugins/bookAssets.ts` 在 dev 时把上一级的 `images/`、`images_original/`
挂到 `/images/**`，构建时整个拷进 `dist/`（设 `BUILD_ASSETS=0` 可跳过拷贝）。
校对台的插图清单也由这个插件在构建期扫描 `images/` 生成，取代了原先 `gen_review.py` 内嵌清单的做法。

## 为什么主力工具是"涂"，不是"输入邻接关系"

一开始只有生成器：输入邻接图，程序算出地图。图一复杂，画出来就很奇怪——尖刺、细条、
小到看不见的块。问题有两层。

**第一层是 bug**，已修，见下面「生成器的画法判据」。

**第二层是这件事本身有难度，不是调参能修好的。** "给定邻接关系画出好看的地图"
在文献里叫 cartogram / rectilinear dual。已知结论大致是：矩形剖分只对很窄的一类图存在，
一般要求内部三角剖分且无分离三角形；放宽到直角多边形之后一般平面图才总有解，
但每块要允许拐好几个角。所以"每块都凸、都圆、都不带尖角"对一般平面图根本无解。
可行的做法是把"好看"当成**能量去优化**，而不是当成约束去构造。

而解析构造恰恰没有优化的余地：`construct.ts` 里的权重只能沿固定线段挪分割点，
动不了长宽比，也拉不直尖角。

还有一层实际考虑：这本书的图是照着扫描件重画的，构图已经定了，不需要算法去发明。
让人直接涂，比让人先把扫描件读成邻接表、再让算法猜回原构图，路径短得多也不容易出错。

于是把地图表示成**一张细网格的着色**，三条链路共用一套数据：人涂网格、机器涂网格、
在网格上做局部搜索。

## 地图绘制台

### 为什么是六边形网格（`core/mesh.ts`）

方格网里四块会在一个角上碰头，于是"对角相邻的两块算不算相邻"没有唯一答案，
描边界时还会出现自己掐自己的夹断点。六边形网格里**每个角点恰好由三个格子共用**，
由此白得两条性质：

1. 两块要么共一条边，要么完全不挨着——不存在"只碰一个点"的暧昧情形；
2. 任何一块格子集合的边界，一定是若干条互不相交的**简单**闭曲线。
   因为一个角点最多只能有两个格子属于同一块，绕这块走时每个角点恰好进一次出一次。

第 2 条是描边界能无歧义翻译的前提，第 1 条是邻接关系有确定答案的前提。

坐标用尖顶六边形、odd-r 偏移。角点 k 位于中心的 `60k - 90` 度方向，于是**第 d 个角点
与第 d+1 个角点之间的那条边，正对第 d 个邻居**——角点表与邻居表用同一个下标对齐，
描边界时不用做任何换算。按下标走一圈是顺时针（屏幕坐标 y 向下），格子落在行进方向的右侧。

### 着色（`core/paint.ts`）

`labels: Int32Array` 每格一个块号，`-1` 是海。空洞、包围、飞地都是着色的自然结果，
不需要专门的构造。存档用游程编码。

判断"把某格从它所在的块里拿走会不会把这块切成两半"只需看六个邻居：
它们首尾相接构成一个六元环，**同色邻居在环上连成一段**时任何穿过该格的路径都能绕过去。
这是 O(1) 的，正是下面局部搜索跑得动的原因。

### 整形（`core/relax.ts`）

在**不动拓扑**的前提下把形状变好看。每次只把一个边界格换个归属，换之前验三条硬约束：

1. 邻接关系一格不差地保持原样（既不许多出来，也不许丢掉）；
2. 失去这一格的那块不能被切断，也不能低于最小面积；
3. 必须保留的公共边界不能短到最小接触长度以下。

三条都是**局部**的：邻接靠一张接触计数表增量维护，连通性靠上面那个六邻居判据。
所以单步是 O(1)，可以放心跑成千上万步；而且每一步都验过，这个循环**不可能**把地图改错。

能量两项。**紧凑度** `周长² / 面积`，归一到"圆块 ≈ 1"（n 环六边形块的极限值是 48）——
尖角要用很多周长换很少面积，所以这一项专治尖刺和细条。**面积均衡** `(面积/目标 - 1)²`，
专治"有一块小得看不见"。

这就是解析构造缺的那个自由度：那边动不了长宽比，这边可以。

### 描边界（`core/trace.ts`）

把着色翻译成现有的 节点 / 弧 / 区域 三件套，于是渲染、手工微调、SVG 导出全都原样复用。

边界图里顶点的度数只可能是 0、2、3。度数 3 就是三块碰头的**交汇点**，正是弧该断开的地方；
度数 2 是弧的内部。弧全局只描一次，两侧区域引用同一条，所以共享边界的几何严丝合缝——
后面拖控制点时仍然是两边一起动，邻接关系不会被拖坏。

标签位置用离散版的极点距离：从这块所有贴着别人的格子同时向内 BFS，走得最远的那格离边界最远。
对细长、带洞、被包住的怪形状都给得出合理位置——用重心的话标签会掉到区域外面去。

### 平滑分三段，各治一段频率（`core/smooth.ts`）

| 手段 | 治什么 |
| --- | --- |
| Chaikin 磨角 | 六边形折线那条 60 度锯齿，最高频 |
| 等距重采样 | 控制点疏密不均。渲染端画的是**均匀参数化**的 Catmull–Rom，疏密不均会在直边上甩出小波浪 |
| Taubin 平滑 | 外框圆角被网格量化出的"走几格下一阶"，低频，磨角磨不掉 |

中间那条容易踩坑：一开始用 RDP 简化，而 RDP 恰好制造疏密不均（弯处密、直处疏），
于是磨完角反而更抖。

Taubin 是一正一负两步交替：单纯的拉普拉斯平滑能压到更低频段，但会让曲线整体缩水，
平滑得越狠区域缩得越小；每个正步后跟一个**略大的负步**，低频几乎原样弹回、高频留在被压下去的
状态，形状就不缩水。三处都保端点不动——那是交汇点，几条弧必须在同一个点上接住。

### 由邻接关系铺草稿（`core/seed.ts`）

**不采样解析构造出来的多边形**，只取那张无交叉的直线画法，逐格问：
离我最近的是哪条边上的哪一半？前一半归 a，后一半归 b。

这是重心细分的离散版，好处是它按定义就是一个**划分**——每格恰好属于一块，
不可能重叠，也不可能翻面。剩下的偏差只有一类：面的度数大于 3 时，那个面上的几块会在
面心附近挤到一起，非相邻的两块可能贴上一两格。这类瑕疵很小而且位置确定，
就地挖成海即可——四块围一圈中间是个小湖，本来就是地图上常见的样子。

之后依次：并飞地 → 挖开多余邻接 → 缝合缺失邻接 → 再挖一次 → 再并一次。
每步修补都用"总毛病数有没有减少"来决定去留，只认比动手之前更好，不要求一步到位。
修不掉的如实报出来，让人手工补，而不是假装草稿就是最终答案。

### 检查

区域为空、断成几片、面积过小、公共边界过短，都在左栏实时列出。
断成几片可以一键「并掉飞地」：每块只留最大的那片，零星几格从边缘一圈圈并给旁边的邻居。

## 生成器是怎么工作的

要解决的问题：**给定一张图，画出一张地图，使得两块区域相邻当且仅当图里有这条边。**

整条链是**确定性**的——不存在"多生成几张碰运气"。同一张图每次得到同一个结果，
一批候选之间只有观感差别（抖动不同），不会有的合法有的不合法。

### 1. 画法判据：不能只看交叉数（`core/planar.ts`、`core/generate.ts`）

先试**洋葱布局**：从某个中心点 BFS 分层，各层摆在同心的圆角矩形环上，
层内按"父节点方位角的平均值"排序减交叉。不行再退回力导向 + 消交叉。

**判据不能只看交叉数。** 顶点滑到一条不相邻的边**上面**时，边与边并没有真正相交，
交叉数照样是 0，可那个顶点周围已经有面被压成零面积了。下一步的重心细分要求面心落在面内，
而这只在面是凸的时候才由"顶点的凸组合仍在面内"保证；面一退化，绕顶点的那一圈扇形就
翻面叠在自己身上。组合上仍然"环闭合、弧两侧对得上"，几何上却是一团互相盖住的乱麻。

> 这曾经是复杂地图画出来特别奇怪的根源。十区域那个用例里，顶点 J 恰好落在边 B-C 上，
> 距离 0；区域轮廓有 6 条自交、2 条翻面，总面积比外框还大三分之一。
> `verifyTopology` 全程放行，因为它只验组合性质，从不验几何不自交。

所以 `nonConvexFaces()` 数凹面，画法按 **交叉数 → 凹面数 → 顶点离非邻接边的距离** 三级排序。
洋葱、Tutte、面积均衡三张结果一起进候选池按同一把尺子挑，而不是"达标就用、不达标退回上一步"——
后者会在 Tutte 明明更好、只是没到阈值时，退回一张更差的画法。

**已知未修**：三角形、树这类内面很少的图，外框展开那段（`spreadAroundCircle`）仍会产出
自交轮廓。可疑点是框上切分点的方向按画布中心算而非分量重心。绕开办法是改用绘制台，
那条链路完全不经过这段代码。

### 2. 平面嵌入（`core/planar.ts`）

有了无交叉的画法，组合嵌入是白送的：每个顶点的邻居按方位角排序即得旋转系统，
沿旋转系统走一圈即得所有的面。不需要跑 Boyer–Myrvold 之类的平面性算法——
画得出无交叉的图，本身就是平面性的构造性证明。

### 3. Tutte 嵌入（`core/tutte.ts`）

把外面的顶点钉在框上，反复把每个内部顶点挪到它邻居的重心。
Tutte 定理（1963）保证：对 3-连通平面图，这样画出来无交叉，且**每个面都是凸的**。

为什么需要它：下一步构造出的区域，面积正比于它周围那些面的面积。
布局里只要有又扁又窄的面，成图里就会出现被挤成一条线的区域。

外圈顶点钉在**内缩**的一圈上而不是外框本身——中间留出的环带就是最外层那些区域的地盘。

### 4. 重心细分构造（`core/construct.ts`）

每个面取一个中心点 c_f，每条边取一个分割点 m_e，则

    区域(v) = 绕着 v 的一圈四边形 (v, m_前, c_f, m_后)

这些四边形把整张图铺满，不留空隙。两个区域的公共边界只可能是 c_f–m_e 这样的线段，
而它出现**当且仅当** e 是一条边——所以：

- 邻接关系由构造保证，不需要事后校验
- 区域(v) 是绕 v 的一圈，**天然连通**，不会出现飞地
- 没有海、没有蜘蛛腿，整个外框被填满

外面没有有限的中心点，改为展开到外框上：外围环游里每个半边分到框上一点，
相邻两点之间的框段就是那个顶点的对外边界——这就形成了"圆角矩形外框 + 径向切分"的样子。

边界的最小单位（弧）是 c_f → m_e → c_f'，恰好一条边对应一条弧。
**弧由两侧区域共享**，所以拖动它时邻接关系天然不会被改坏，两块的轮廓也永远严丝合缝。

### 5. 面积均衡

c_f 与 m_e 具体放在哪里是**完全自由**的（只要 m_e 在边的内部、c_f 在面的内部），
挪动它们不改变任何邻接关系。于是可以拿它做面积再分配：反复量各区域面积、调整权重、重建。

**局限**：这只能沿固定线段挪分割点，动不了形状的长宽比，也拉不直尖角。
要真正整形请用绘制台——那边是在网格上做局部搜索，自由度完全不同。

### 6. 渲染

每段弧**独立**做平滑，而不是把整个环拼起来再平滑——否则同一条边界在两侧区域里
会算出略微不同的曲线，接缝处露白。

地图 SVG 一定要写出 `width`/`height`。只给 `viewBox` 的话它的默认尺寸是 100%×100%，
会撑满窗格再靠 `preserveAspectRatio` 把图放大塞进去，屏幕越宽图画得越大，
边框粗细和字号跟着放大，屏上所见和导出的 900×640 对不上；元素比图大出的那圈黑边
还会让拖控制点的坐标整体偏移。同理，画布的 `max-width`/`max-height` 要顶到模型尺寸而不是
`100%`，因为 canvas 的固有尺寸取自按设备像素比放大过的 `width`/`height` 属性。

## 刷新之后还在吗

在。三个标签页的状态都存在浏览器 localStorage 里（`src/core/persist.ts`），
关页、刷新、切标签页都不丢：

| 键 | 存什么 |
| --- | --- |
| `fct-tab-v1` | 上次停在哪个标签页 |
| `fct-paint-v1` | 绘制台的画布（区域名、配色、着色的游程编码） |
| `fct-paint-opts-v1` | 绘制台的工具、笔刷、网格密度、整形参数、草稿文本 |
| `fct-review-v1` | 校对进度（通过/待改/意见/时间） |
| `fct-review-ui-v1` | 停在哪一张、开着什么筛选、意见框里还没提交的草稿 |
| `fct-gen-draft-v1` | 生成器的邻接图、风格、自绘外框、配色方案、随机种子 |
| `fct-gen-batch-v1` | 上次生成的那一批候选 |
| `fct-gen-model-v1` | 正在编辑的那张地图（离开编辑器时清掉） |

分几条存而不是打成一包，是因为它们的变化频率差着两个数量级：
拖一下边界，`model` 每一帧都是新的，而那一批候选将近一兆——
打成一包的话，每拖一下都要把整批候选重新序列化一遍。

写入统一走防抖（`usePersist`），并在页面隐藏时补一次立即写入，
免得"改完马上按 F5"正好落在防抖窗口里。
读出来的一律当作不可信输入校验一遍，对不上就整份丢掉，宁可从头开始
也不要把上一版程序留下的半截状态铺开。

浏览器不给用本地存储时（隐私模式等）功能照常，只是不留痕，界面上会有提示。

## 校对进度从哪来

localStorage 是按 origin 隔离的：旧的 `review.html` 多半是 `file://` 双击打开的，
和本应用不共享数据。所以校对台在本地进度为空时，会自动读项目根目录的
`review_result.json` 打底，把上一轮的成果接上（本地已有记录则不动）。

工具栏的「导入进度」认两种格式，两种都会**合并**进现有进度而不是覆盖：

- 校对台导出的 `review_result.json`
- 旧版 localStorage 里的原始结构 `{ "fig-001": { status, comment, at }, … }`
  （在旧页面的控制台里执行 `copy(localStorage.getItem('fct-review-v1'))` 就能拿到）

## 测试

```bash
pnpm paint-test    # 涂色链路：描边界闭合性、空洞表示、整形不动拓扑、存档往返
pnpm smoke         # 生成算法：各用例每一张候选都必须合法，已知非平面的必须失败
pnpm parse-test    # 邻接图文本输入的解析
pnpm progress-test # 校对进度导入
```

`paint-test` 验的四条不变量撑起了整条涂色链路：

1. **描边界不丢不乱**：每块的边界环首尾相接并闭合，弧两侧的区域对恰好等于从格子上量出来的邻接关系；
2. **空洞能表示**：一块被另一块整个包住时，外面那块要描出两条环；
3. **整形不动拓扑**：跑完局部搜索，邻接关系一条不差，每块仍然连通，隔离带没被捅穿；
4. **整形确实变好看**：总能量与最差紧凑度都要下降。
