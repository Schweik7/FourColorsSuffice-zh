# 《四色足矣》插图工作台

Vite + React + TypeScript。两个标签页：

- **SVG 生成器** —— 给一张邻接图，生成对应的四色地图 SVG，可继续编辑、导出、再导入
- **插图校对台** —— 原书扫描件与重绘 SVG 并排对照审阅（原来的 `review.html`）

```bash
pnpm install
pnpm dev        # http://localhost:5173
pnpm build      # 产物在 dist/
pnpm test       # 输入解析 + 校对进度导入 + 生成算法，三套
```

`pnpm smoke --write` 会把各个用例生成的 SVG 落到 `scripts/out/`，方便肉眼检查。

插图不在本目录里——`plugins/bookAssets.ts` 在 dev 时把上一级的 `images/`、`images_original/`
挂到 `/images/**`，构建时整个拷进 `dist/`（设 `BUILD_ASSETS=0` 可跳过拷贝）。
校对台的插图清单也由这个插件在构建期扫描 `images/` 生成，取代了原先 `gen_review.py` 内嵌清单的做法。

## 校对进度从哪来

localStorage 是按 origin 隔离的：旧的 `review.html` 多半是 `file://` 双击打开的，
和本应用不共享数据。所以校对台在本地进度为空时，会自动读项目根目录的
`review_result.json` 打底，把上一轮的成果接上（本地已有记录则不动）。

工具栏的「导入进度」认两种格式，两种都会**合并**进现有进度而不是覆盖：

- 校对台导出的 `review_result.json`
- 旧版 localStorage 里的原始结构 `{ "fig-001": { status, comment, at }, … }`
  （在旧页面的控制台里执行 `copy(localStorage.getItem('fct-review-v1'))` 就能拿到）

## 刷新之后还在吗

在。两个标签页的状态都存在浏览器 localStorage 里（`src/core/persist.ts`），
关页、刷新、切标签页都不丢：

| 键 | 存什么 |
| --- | --- |
| `fct-tab-v1` | 上次停在哪个标签页 |
| `fct-review-v1` | 校对进度（通过/待改/意见/时间） |
| `fct-review-ui-v1` | 停在哪一张、开着什么筛选、意见框里还没提交的草稿 |
| `fct-gen-draft-v1` | 生成器的邻接图、风格、自绘外框、配色方案、随机种子 |
| `fct-gen-batch-v1` | 上次生成的那一批候选 |
| `fct-gen-model-v1` | 正在编辑的那张地图（离开编辑器时清掉） |

分三条存而不是打成一包，是因为它们的变化频率差着两个数量级：
拖一下边界，`model` 每一帧都是新的，而那一批候选将近一兆——
打成一包的话，每拖一下都要把整批候选重新序列化一遍。

写入统一走防抖（`usePersist`），并在页面隐藏时补一次立即写入，
免得「改完马上按 F5」正好落在防抖窗口里。
读出来的一律当作不可信输入校验一遍，对不上就整份丢掉，宁可从头开始
也不要把上一版程序留下的半截状态铺开。

浏览器不给用本地存储时（隐私模式等）功能照常，只是不留痕，界面上会有提示。

## 生成器是怎么工作的

要解决的问题：**给定一张图，画出一张地图，使得两块区域相邻当且仅当图里有这条边。**

整条链是**确定性**的——不存在「多生成几张碰运气」。同一张图每次得到同一个结果，
一批候选之间只有观感差别（抖动不同），不会有的合法有的不合法。

### 1. 无交叉的直线画法（`core/onion.ts`、`core/layout.ts`）

先试**洋葱布局**：从某个中心点 BFS 分层，各层摆在同心的圆角矩形环上，
层内按「父节点方位角的平均值」排序减交叉。中心点与环形形状都是穷举试遍、取交叉最少的一版。
不行再退回力导向 + 消交叉。

这是整条链上**唯一**可能失败的一步，而它失败就等于「这个图不是平面图」——
地图的邻接图一定是平面图，反之亦然。

### 2. 平面嵌入（`core/planar.ts`）

有了无交叉的画法，组合嵌入是白送的：每个顶点的邻居按方位角排序即得旋转系统，
沿旋转系统走一圈即得所有的面。不需要跑 Boyer–Myrvold 之类的平面性算法——
画得出无交叉的图，本身就是平面性的构造性证明。

### 3. Tutte 嵌入（`core/tutte.ts`）

把外面的顶点钉在框上，反复把每个内部顶点挪到它邻居的重心。
Tutte 定理（1963）保证：对 3-连通平面图，这样画出来无交叉，且**每个面都是凸的**。

为什么需要它：下一步构造出的区域，面积正比于它周围那些面的面积。
布局里只要有又扁又窄的面，成图里就会出现被挤成一条线的区域。

外圈顶点钉在**内缩**的一圈上而不是外框本身——中间留出的环带就是最外层那些区域的地盘。

### 4. 重心细分构造（`core/construct.ts`）

每个面取一个中心点 c_f，每条边取一个分割点 m_e，则

    区域(v) = 绕着 v 的一圈四边形 (v, m_前, c_f, m_后)

这些四边形把整张图铺满，不留空隙。两个区域的公共边界只可能是 c_f–m_e 这样的线段，
而它出现**当且仅当** e 是一条边——所以：

- 邻接关系由构造保证，不需要事后校验
- 区域(v) 是绕 v 的一圈，**天然连通**，不会出现飞地
- 没有海、没有蜘蛛腿，整个外框被填满

外面没有有限的中心点，改为展开到外框上：外围环游里每个半边分到框上一点，
相邻两点之间的框段就是那个顶点的对外边界——这就形成了「圆角矩形外框 + 径向切分」的样子。

边界的最小单位（弧）是 c_f → m_e → c_f'，恰好一条边对应一条弧。
**弧由两侧区域共享**，所以拖动它时邻接关系天然不会被改坏，两块的轮廓也永远严丝合缝。

### 5. 面积均衡

c_f 与 m_e 具体放在哪里是**完全自由**的（只要 m_e 在边的内部、c_f 在面的内部），
挪动它们不改变任何邻接关系。Tutte 保证了面是凸的，所以面心取顶点的任意凸组合都仍在面内。

于是可以拿它做面积再分配：反复量各区域面积、调整权重、重建。
权重大的区域，边上的分割点被推得离它更远、面心也被推开，地盘就变大。
这比挪顶点安全得多——挪顶点要担心破坏平面性，挪细分点不用。

**已知的局限**：度数低又被夹在两个外圈顶点之间的顶点（它和邻居构成的三角形本身就是扁的），
面积仍会明显小于平均值。地图是正确的，只是那一块偏小。可以在编辑器里手动拖边界调整。

### 6. 渲染

每段弧**独立**做平滑，而不是把整个环拼起来再平滑——否则同一条边界在两侧区域里
会算出略微不同的曲线，接缝处露白。

## 配色

色号来自 `_redraw_tools/GUIDE.md` 与正文 fig-102：

| 方案 | 红 | 绿 | 黄 | 蓝 | 灰 |
| --- | --- | --- | --- | --- | --- |
| 标准四色 | `#c0504d` | `#5a9257` | `#e0b23c` | `#4f7cac` | `#6f6f6f` |
| 淡色（fig-102 同款） | `#e8c0bf` | `#c4d8c3` | `#f4e3b9` | `#c0d0e1` | `#d9d9d9` |
| 全灰 | `#8a8a8a` | `#a8a8a8` | `#c6c6c6` | `#e4e4e4` | `#6f6f6f` |

每个区域也可以单独填十六进制色号。「自动四色」用回溯法求解；
输入的图非平面时无解，此时退回贪心并用灰色兜底。
