# 《四色足矣》插图工作台

Vite + React + TypeScript。两个标签页：

- **SVG 生成器** —— 给一张邻接图，生成对应的四色地图 SVG，可继续编辑、导出、再导入
- **插图校对台** —— 原书扫描件与重绘 SVG 并排对照审阅（原来的 `review.html`）

```bash
pnpm install
pnpm dev        # http://localhost:5173
pnpm build      # 产物在 dist/
pnpm test       # 解析器测试 + 生成算法冒烟测试
```

`pnpm smoke --write` 会把各个用例生成的 SVG 落到 `scripts/out/`，方便肉眼检查。
`node node_modules/.tmp/dbg.mjs` 之外还有 `scripts/debug-raster.ts`，能把栅格打成 ASCII，排查区域分裂时很好用。

插图不在本目录里——`plugins/bookAssets.ts` 在 dev 时把上一级的 `images/`、`images_original/`
挂到 `/images/**`，构建时整个拷进 `dist/`（设 `BUILD_ASSETS=0` 可跳过拷贝）。
校对台的插图清单也由这个插件在构建期扫描 `images/` 生成，取代了原先 `gen_review.py` 内嵌清单的做法。

## 生成器是怎么工作的

要解决的问题：**给定一张图，画出一张地图，使得两块区域相邻当且仅当图里有这条边。**

### 1. 平面画法（`core/layout.ts`）

力导向布局，外加一项「顶点远离与它无关的边」的斥力。多次随机重启取交叉最少的一版，
再用两招做局部改良：交换两个顶点的位置；把某个顶点收到它所有邻居的重心
（Tutte 嵌入的做法——K4 这类图力导向总把四个点摊成一圈从而交叉，把一个点收进三角形内部就解决了）。

### 2. 栅格约束生长（`core/grow.ts`）

整个算法的地基是一条局部约束：

> 一格能判给区域 `r`，当且仅当以它为中心、切比雪夫半径 `guard` 的方块内，
> 不存在与 `r` 不相邻的区域。

有了它，地图上**不可能**冒出图里没有的邻接关系；不相邻的两块之间会自动留出一条看得见的水道。

生长本身分两阶段：

1. **只播圆盘种子**，按面积均衡分轮扩张（每轮只让面积最小的那几个区域各长一层）。
   这样长出来的是有块面感的地图。若改用同步 BFS，被围住的区域永远长不大，成图是一堆细长的「蜘蛛腿」。
2. 检查哪些该有的邻接没自然长出来，**只给那几条边补一条细带子**再重来，最多补三轮。
   带子是纵向劈成两半的长条，两半分属两个端点，于是它们沿中线相接——
   这是「每个平面图都是某张地图的邻接图」的标准构造，能强行做出任何一条需要的邻接。
   绝大多数图第一轮就成，一条带子都不用补。

种子的尺寸受「净空」约束：布局难免把某个顶点摆得离一条与它无关的边很近，
圆盘一大就会盖穿那条边带，把两侧区域各切成两截。

最后做一次平滑，把锯齿边界揉圆。三道保险：骨架格冻结不动（必需的邻接揉不没）、
改写前过一遍上面那条约束（揉不出多余的邻接）、只动形态学意义上的「简单点」（区域不会被拧成两瓣）。

### 3. 栅格 → 可编辑拓扑（`core/trace.ts`）

在格点构成的格线上，分隔了两个不同归属的那一小段就是「边界基元」。把它们串起来：
度数 ≠ 2 的格点是**交汇点（node）**，两个交汇点之间的链是一段**弧（arc）**。

**弧是编辑的最小单位，两侧区域共用同一条弧** —— 所以拖动它时邻接关系天然不会被改坏，
两个区域的轮廓也永远严丝合缝。同理，渲染时每段弧**独立**做平滑，
而不是把整个环拼起来再平滑，否则同一条边界在两侧区域里会算出略微不同的曲线，接缝处露白。

开工前会先消除「棋盘格点」（两个同归属格子只在对角相碰）——这种点在拓扑上是歧义的，
会让区域边界在同一格点上出现 4 条边而无法唯一串成环。

### 4. 校验

生成完把地图上**真正做出来**的邻接关系读回来，与输入的图逐条比对，
再检查有没有区域被撕成几块或干脆没画出来。对不上就换个随机种子重来（最多 5 次），
仍然不行就返回最接近的一版并如实报告差异——多半是输入的图本身非平面（K5、K3,3 画不出地图）。

### 5. SVG 往返（`core/serialize.ts`）

导出时把完整模型以 JSON 塞进 `<metadata>` 里的 `<fcs:model>`，带协议号与版本号。
把导出的 SVG 拖回生成器就能接着改边界、配色和标签。

## 配色

色号来自 `_redraw_tools/GUIDE.md` 与正文 fig-102：

| 方案 | 红 | 绿 | 黄 | 蓝 | 灰 |
| --- | --- | --- | --- | --- | --- |
| 标准四色 | `#c0504d` | `#5a9257` | `#e0b23c` | `#4f7cac` | `#6f6f6f` |
| 淡色（fig-102 同款） | `#e8c0bf` | `#c4d8c3` | `#f4e3b9` | `#c0d0e1` | `#d9d9d9` |
| 全灰 | `#8a8a8a` | `#a8a8a8` | `#c6c6c6` | `#e4e4e4` | `#6f6f6f` |

每个区域也可以单独填十六进制色号。「自动四色」用回溯法求解；
输入的图非平面时无解，此时退回贪心并用灰色兜底。
